## Decisions taken while the user was away

Surface decisions the implementation session took on its own, each reversible
and flagged for review. Design questions go to the "finga" session instead.

1. **Placeholder folders.** Page 1 lists the whole tree; step 00 creates the top-level folders and `cmd/gameserver`, `cmd/migrate` with `.gitkeep` files. The `internal/` subtree arrives with the steps that fill it, so no empty package directories sit in the repository.
2. **`make test` runs Go tests only** until `web/` exists (page 1 says it also runs the web tests); the client steps add `npm test`.
3. **CI** installs golangci-lint through its official action and then runs the Makefile targets, so CI and a laptop run the same commands. A Postgres service joins the workflow in step 02, when the first repository tests need it.
4. **`pkg/configload` is byte-identical to docviewer's** apart from the module path in the test file's import. The comment naming `DOCVIEWER_SERVER_ADDR` as an example was left as is, to keep the copy diffable.
5. **Docker Desktop was started by the agent** to run `make up`; it was left running.
6. **`model.Class` lists all four classes** (the column comment on page 2 names them); which classes a player can pick is game data's call, so Stage 1's Warrior and Bowman restriction lives in `data/classes.yaml` (step 04), not in the type.
7. **Two cross-field rules in `config.Validate`:** `database.url` must have a `postgres://` or `postgresql://` scheme, and `world.tick_rate_hz` must divide 60 (at most 60), so each tick holds a whole number of the simulation's 1/60 s sub-steps (page 5). Page 1 only lists the sections; these rules are the implementation's reading of pages 3 and 5.
8. **`pkg/errs` shape:** `New(code, message)`, `Invalid(message)`, `(*Error).Wrap(cause)` returning a copy (so sentinels stay immutable and `errors.Is(copy, sentinel)` holds through code and message equality), `CodeOf` and `MessageOf` taking the outermost `errs` value in the chain, and `InternalMessage` for errors without one. `Error()` includes the cause for logs; `Message` never does.
9. **Metric names are exactly page 3's** (`tick_duration_seconds`, no `finga_` prefix), registered on a registry built by `pkg/observability.NewRegistry` with the Go and process collectors. `Metrics.ObserveTick` records the duration and counts an overrun when a tick exceeds its interval.
10. **`dbx.Beginner` is `BeginTx`, not `Begin`,** so `InTx` names READ COMMITTED explicitly instead of relying on the server default; `InTx` also takes options (`OnRetry`, `MaxAttempts`) so a store can feed `db_tx_retries_total`. Page 1's sketch was updated in the same step.
11. **`pkg/pgtest` is generic:** it takes a `MigrateFunc` rather than importing `migrations`, starts `postgres:17-alpine` with Testcontainers, or uses an existing server when `PGTEST_URL` is set (faster locally, and a way round Docker socket trouble). Each test gets `CREATE DATABASE ... TEMPLATE` of a template prepared once per package test run, dropped by `t.Cleanup`.
12. **Port 5432 on this machine belongs to a local PostgreSQL 17 service** (`postgresql-x64-17`), which was left running: stopping a service is the user's call. The Compose file publishes Postgres on `FINGA_POSTGRES_PORT` (default 5432, read by docker-compose from the shell), and the design's default URL is unchanged.
13. **Movement state and conventions for the TypeScript port** (page 5 names the constants, not the representation): position is the centre of the feet, the box is half-open so a box flush with an edge does not touch it, `State` carries `Ground` (platform index stood on), `DropPlatform` and `DropTimer`, Facing is 1 or -1, and `Step`'s nine phases are listed in its godoc in the order the port must follow. Jump is "held" (holding it re-jumps on landing); a tap is one sub-step. Jump from a rope is a full jump with walking speed from Left/Right.
14. **Vector expectations are generated** by `go test ./internal/application/world/sim -run TestVectors -update` from the Go implementation and reviewed by hand; the behaviour table in `sim_test.go` is what proves the rules, the vectors pin the exact floats for the client.
15. **`data/movement.yaml` holds the movement constants** (page 5 says numbers live in game data; page 2's file list didn't name a file for them). Page 2 now lists it. `gamedata.Movement()` returns them as `sim.Params`, and `TestRealDataLoads` checks they equal `sim.DefaultParams()`, which the vectors were generated with.
16. **Base primary stats per class** (page 5 gives formulas, not level-1 stats): Warrior STR 12 DEX 5 INT 4 AGI 5 VIT 10; Bowman STR 5 DEX 12 INT 4 AGI 10 VIT 5, in `classes.yaml` as `base_stats`, beside the Stage 1 `level_up_points` preset (validated to add up to 5).
17. **Map conventions beyond page 5:** a map-level Tiled property `kind` (`town` or `hunting`); all six object layers are required even when empty; a town may not have spawns; exactly one `player_spawn` object, whose bottom centre is the spawn point; a portal's arrival point is the bottom centre of the target portal; map IDs are file names. `stats.yaml` is keyed by class, then by the nine derived stats, each with `base`, `per_level`, `coef` and `cap`; rates are fractions.
18. **Stage 1 content:** town (1280 × 640), forest (levels 1 to 10: green slime, orange mushroom) and cave (10 to 20: wild boar, cave bat), chained by portals; 12 items (6 equip, 2 use, 4 etc). The product's third hunting map (20 to 30) is Stage 2 content.
19. **Repository interface names:** revive's stutter check (part of docviewer's lint config) rejects `account.AccountRepository`, so a module's own aggregate repository is `Repository` and the others keep their noun (`SessionRepository`). Page 1's example (`item.ItemRepository`) was updated to match.
20. **Logins are serialised per account** with `SELECT ... FOR UPDATE` on the account row inside the login transaction, before revoking and inserting; the `one_active_session` index stays the backstop and a violation runs the transaction once more, as the step page says. The design notes only named the index.
21. **Session lifetime is a fixed 7 days** (`Options.SessionTTL`), pending step 16 (TD-24); the login throttle is 5 per minute per username and per IP (page 4) and consumes a token on every attempt, not only failures.
22. **An unknown username fails without a dummy hash verification,** so a login for a missing user returns faster than one with a wrong password. The response is identical; only timing differs. Flagged for the finga session as a possible hardening item in step 16.
23. **Character names:** 3 to 12 characters, letters and digits, starting with a letter (A2 says "length, allowed characters" without numbers; page 4 only said "name and class"). Page 4 now states the rule beside the username rule.
24. **Rounding of derived stats:** max HP and MP round down to whole points (the table stores ints); attack power, accuracy, evasion, defense and the rates stay fractional for the damage formula. Page 5 now says so.
25. **No character-slot limit in Stage 1:** A3 (slots and select, OD-09 default 3) is P1, so `Create` does not count an account's characters. Trivial to add when A3 arrives.
26. **`DeathPenalty` at the level cap does nothing,** since EXP stops accumulating there; `AwardExp` at the cap resets EXP to 0 and asks the plan for each new level with that level number, so a Stage 2 player-choice plan can look up queued allocations.
